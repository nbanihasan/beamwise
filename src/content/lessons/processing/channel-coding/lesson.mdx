## Redundancy with structure

A channel encoder takes $k$ information bits and outputs $n > k$ coded bits. The ratio $R = k/n$ is the **code rate**. The extra $n-k$ bits are not random padding: they are chosen so that valid codewords differ from each other in at least $d_{\min}$ positions. A decoder can then correct up to $t = \lfloor (d_{\min}-1)/2 \rfloor$ errors per codeword.

The payoff is **coding gain**: the same bit error rate at a lower SNR. A few dB of coding gain is worth a lot in optical wireless, where every dB of SNR costs LED power, detector area or range.

## Block codes

**Hamming codes** <Cite id="hamming1950" /> are the simplest: Hamming(7,4) adds 3 parity bits so that three overlapping parity checks (the circles above) pin down any single error. Decoding is a lookup: the **syndrome** $\mathbf{s} = \mathbf{H}\mathbf{r}^\top$ is zero for a valid word and otherwise *equals the column of $\mathbf{H}$ at the error position*.

**Reed–Solomon codes** <Cite id="reed1960" /> work on symbols (usually bytes) instead of bits. RS($n,k$) corrects $(n-k)/2$ wrong *symbols*, and a symbol is wrong whether one or all eight of its bits flipped. That makes RS codes excellent against bursts. IEEE 802.15.7 uses RS codes as the outer code of its PHY I and PHY II modes <Cite id="ieee802157" />.

## Convolutional codes and Viterbi

A convolutional encoder is a shift register: each output bit is a parity of the current and the previous $K-1$ input bits. There are no blocks; the code is a path through a **trellis** of $2^{K-1}$ states. The **Viterbi algorithm** <Cite id="viterbi1967" /> finds the most likely path, and it can use *soft* inputs (how confident each received sample is), worth about 2 dB over hard decisions. The K = 7, rate-½ code with generators (171, 133) octal is the classic; 802.15.7 PHY I uses convolutional inner codes with RS outer codes.

## Inside an LDPC decoder

An LDPC code is defined by a sparse parity-check matrix $\mathbf{H}$, drawn as a **Tanner graph**: one node per bit, one per parity check, and an edge wherever $\mathbf{H}$ has a 1. Decoding is local message passing on that graph <Cite id="kschischang2001" />. In Gallager's **bit-flipping** decoder each bit counts how many of its checks fail and the worst offenders flip. In **belief propagation** (here its hardware-friendly min-sum form) bits and checks exchange soft log-likelihood ratios until every check is satisfied. Each node only talks to a few neighbours, so thousands can be updated in parallel, which is why LDPC dominates high-speed standards.

<KeyIdea title="Interleaving turns bursts into scattered errors">
Optical channels fail in bursts: a hand crossing the beam, a scintillation fade, a lamp flicker. Codes are designed for scattered errors. An **interleaver** shuffles coded bits before transmission, so after de-interleaving a burst is spread across many codewords, each with only an error or two. ## Line codes are not error-correcting codes

**Run-length-limited (RLL) codes** such as Manchester, 4B6B and 8B10B also add redundancy, but for a different purpose: guaranteeing transitions and a constant average brightness so the lamp never visibly flickers and the receiver keeps its clock <Cite id="ieee802157" />. A typical VLC transmitter therefore cascades **FEC → interleaver → RLL line code → modulator**.
